# Terraform Module Skeleton

This repository contains a skeleton for creating new Terraform modules with built-in testing using the [Terraform Terratest Framework](https://github.com/matthew-dresden/terraform-terratest-framework/blob/main/README.md).

## Getting Started

### Prerequisites

- [Terraform](https://www.terraform.io/downloads.html) >= 1.12.1
- [Go](https://golang.org/doc/install) >= 1.23
- [asdf](https://asdf-vm.com/) for version management

### Clone the Skeleton

To start a new module from this skeleton:

```bash
# Clone the skeleton to a new directory
git clone https://github.com/your-org/terraform-modules.git
cd terraform-modules
cp -r skeletons/generic-skeleton your-new-module

# Initialize the new module
cd your-new-module
rm -rf .git
git init
```

### Configure mpm and Install Dependencies

This module uses [mpm](https://github.com/matthew-dresden/mpm), a self-contained manifest package manager, for automation tasks. Install the CLI once with `pipx install git+https://github.com/matthew-dresden/mpm@v1.0.0`, then:

```bash
# Step 1: Configure mpm (installs asdf, tools, and resolves automation packages)
make mpm-configure

# Step 2: Install module dependencies (Go modules, tftest CLI)
make install
```

**What `make mpm-configure` does:**
1. Installs asdf v0.15.0 (if not already installed)
2. Installs tools from `.tool-versions` (Terraform, Go, etc.)
3. Installs the `mpm` CLI (via pipx) if it is not already on PATH
4. Runs `mpm install`, resolving every `MPM_SOURCE_*` block in `.mpm` against `.mpm.lock` and aggregating the resulting packages into `.packages/`
5. Makes the mpm-provided automation tasks available (test, lint, format, docs, security)

**What `make install` does:**
1. Installs Go module dependencies
2. Installs the `tftest` CLI tool
3. Prepares the module for running tests

**Important:** 
- The base Makefile only provides `mpm-configure` and other mpm management targets
- All other tasks (test, lint, format, etc.) are delivered by mpm packages after running `make mpm-configure`
- You must run `make install` after `make mpm-configure` to install module dependencies
- The `.packages/` and `.mpm-data/` directories are ephemeral and regenerated by `make mpm-configure`
- These directories are automatically git-ignored and should never be committed

## Writing Tests

### Using the TestCtx Package

The `testctx` package is the core of the Terraform Terratest Framework, providing the essential functionality for running and managing Terraform tests. It offers several key functions:

- **RunSingleExample**: Runs a specific example with the given configuration
  ```go
  ctx := testctx.RunSingleExample(t, "../../examples", "basic", testctx.TestConfig{
      Name: "basic-test",
  })
  ```

- **RunAllExamples**: Runs all examples in parallel
  ```go
  results := testctx.RunAllExamples(t, "../../examples", configs)
  ```

- **DiscoverAndRunAllTests**: Automatically discovers and runs all examples
  ```go
  testctx.DiscoverAndRunAllTests(t, "../../", func(t *testing.T, ctx testctx.TestContext) {
      // Common assertions for all examples
  })
  ```

For more detailed documentation on the testctx package, see the [TestCtx Package Documentation](https://github.com/matthew-dresden/terraform-terratest-framework/blob/main/docs/TESTCTX_PACKAGE.md).

> **Note:** The `tftest` CLI tool, provided by the Terraform Terratest Framework, is required for running tests and is installed via `make install` (delivered by an mpm package). This ensures the tool is available for both CI/CD and local development.

### Using Assertions

The framework provides a set of assertions in the `pkg/assertions` package that you can use to verify your Terraform module's behavior:

```go
import (
    "testing"

    "github.com/matthew-dresden/terraform-terratest-framework/pkg/assertions"
    "github.com/matthew-dresden/terraform-terratest-framework/pkg/testctx"
)

func TestExample(t *testing.T) {
    ctx := testctx.RunSingleExample(t, "../../examples", "example", testctx.TestConfig{
        Name: "example-test",
    })
    
    // Use assertions
    assertions.AssertOutputEquals(t, ctx, "instance_type", "t2.micro")
    assertions.AssertOutputContains(t, ctx, "bucket_name", "my-bucket")
    assertions.AssertOutputMapContainsKey(t, ctx, "tags", "Environment")
}
```

For a complete list of available assertions, see the [Assertions Documentation](https://github.com/matthew-dresden/terraform-terratest-framework/blob/main/docs/ASSERTIONS.md).

### Common Tests

Common tests run on all examples and verify basic functionality:

- **Idempotency**: Automatically included by the framework - ensures that applying the same Terraform code multiple times produces the same result
- **Validation**: Verifies that the Terraform code is syntactically valid
- **Formatting**: Checks if the Terraform code is properly formatted
- **Required Outputs**: Ensures that all required outputs are defined
- **Input Validation**: Verifies that inputs from terraform.tfvars match the provisioned outputs

See the [Common Tests README](./tests/common/README.md) for more details on these tests and how to control idempotency testing.

### Example-Specific Tests

Each example has its own tests that verify specific functionality:

- **Basic Example**: Tests the basic functionality of the module
- **Advanced Example**: Tests more complex configurations and features

See the [Basic Tests README](./tests/basic/README.md) and [Advanced Tests README](./tests/advanced/README.md) for more details.

## Variable Management

Each example uses a consistent approach to variable management:

1. **variables.tf**: Defines variables with default values
2. **terraform.tfvars**: Sets actual values for the example
3. **main.tf**: References variables instead of hardcoded values

This approach:
- Makes examples more maintainable
- Allows for dynamic testing
- Follows Terraform best practices

## Running Tests

**First, configure mpm and install dependencies:**
```bash
make mpm-configure  # Resolve the mpm automation packages
make install        # Install Go dependencies and tftest CLI
```

**Then use the provided automation tasks:**

```bash
# Testing
make test              # Run all Terratest tests
make test-common       # Run common tests only
make tf-test           # Run Terraform tests with test.config environment
make test-all          # Run comprehensive test suite (lint, format, docs, plan, security, tests)

# Terraform
make tf-format         # Check Terraform formatting
make tf-format-fix     # Fix Terraform formatting
make tf-lint           # Lint Terraform files
make tf-plan           # Run terraform plan for examples
make tf-security       # Run security checks with tfsec
make tf-docs           # Generate Terraform documentation
make tf-docs-check     # Verify documentation is up-to-date

# Go
make go-lint           # Lint Go test files
make go-format         # Format Go test files

# Cleanup
make clean             # Remove Terraform state and cache files
make clean-all         # Clean everything including Go cache

# mpm Management
make mpm-clean         # `mpm clean` -- tear down .packages/ and .mpm-data/
make mpm-configure     # Re-resolve and install the mpm packages
make mpm-list          # `mpm list` -- declared vs installed sources
make mpm-validate      # `mpm validate lockfile` -- fail on declared/installed drift
```

You can also run specific Go tests directly:

```bash
go test ./tests/common -run '^TestInputsMatchProvisioned'
```

**Note:** The base Makefile only provides `mpm-*` targets. All other tasks (test, lint, format, docs, security) are delivered by the `terraform-module-build` mpm package and are only available after running `make mpm-configure` followed by `make install`.

## mpm Configuration

This module's package sources live in `.mpm`. mpm discovers the file natively by walking up from the working directory; make never sources it.

```properties
MPM_SOURCE_build_URL=https://github.com/matthew-dresden/mpm.git
MPM_SOURCE_build_REF=refs/tags/1.0.0
MPM_SOURCE_build_PATH=repo-specs/terraform/terraform-modules-monorepo/modules/meta.xml
MPM_SOURCE_build_NAME=terraform-module-build
MPM_SOURCE_build_GITBASE=https://github.com/matthew-dresden/
```

Sources are auto-discovered from the `MPM_SOURCE_<name>_URL` keys and processed in alphabetical order. Every resolved source is pinned in the sibling `.mpm.lock`, which is committed.

**To add a source:**

```bash
mpm add <entry> --catalog-source https://github.com/matthew-dresden/mpm.git@1.0.0
make mpm-configure
```

**To update mpm packages:**
1. Bump `MPM_SOURCE_build_REF` in `.mpm`
2. Run `make mpm-configure` (rewrites `.mpm.lock`)
3. Run `make mpm-validate` to confirm the lock and the manifest agree

**Note:** The `Makefile` is a static template that rarely changes. All source configuration is in `.mpm`.

## Developer Workflow

1. **Clone the skeleton**: Start by cloning this skeleton to a new directory
2. **Configure mpm**: Run `make mpm-configure` to resolve and install automation packages
3. **Install dependencies**: Run `make install` to install Go modules and tftest CLI
4. **Modify the module**: Update the module code to implement your functionality
5. **Update examples**: Modify the examples to demonstrate your module's usage
6. **Write tests**: Update the tests to verify your module's functionality
7. **Run tests**: Run the tests using `make test`
8. **Commit and push**: Commit your changes, including `.mpm.lock` (`.packages/` and `.mpm-data/` are git-ignored)
